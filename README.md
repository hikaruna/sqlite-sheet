# SQLiteシート

**JOIN や正規化ができる、1シート＝1テーブルの Google スプレッドシート。**
ブラウザだけで動く SQLite クライアントです。サーバー不要、データは端末の OPFS に保存されます。

## できること

- **スプレッドシートの操作感**：セルを選んで打てば即 `UPDATE`。矢印/Tab/Enter 移動、範囲選択、`Ctrl+C / V`（Excel・Google スプレッドシートと TSV で相互にコピペ）、`Ctrl+D` 下へコピー、`Ctrl+Z / Y` 元に戻す・やり直し
- **最下行に打てば行の追加**、貼り付けがはみ出せば複数行をまとめて `INSERT`（1トランザクション。1つでも失敗すれば全部取り消し）
- **3種類のシート**：テーブル ▦（編集可）／ビュー ◫／クエリ ⌕（任意の `SELECT`。「ビューとして保存」で昇格）
- **設計パネル（⚙ 設計）**：列の型・NOT NULL・DEFAULT・CHECK・COLLATE・生成列、**複合 PRIMARY KEY、複数の UNIQUE、複数列の FOREIGN KEY（ON DELETE/UPDATE）**、表の CHECK、`STRICT` / `WITHOUT ROWID` / `AUTOINCREMENT`、インデックス
  - ALTER TABLE でできない変更（型やキーの変更など）も、データを保ったまま公式手順でテーブルを作り直して反映。実行前に SQL を確認できます
- **外部キーが見える**：参照先の名前をセルに併記、`Alt+↓` で参照先から選択、`Ctrl+クリック` で参照先へジャンプ、列メニューから JOIN 済みのクエリを作成
- **SQL コンソール（`Ctrl+\``）**：GUI でできないことは SQL で。GUI が発行した SQL もすべて「実行履歴」に残ります
- **正規表現の関数**：`REGEXP` 演算子、`regexp_like(文字列, パターン)`、`regexp_substr(文字列, パターン)`、`regexp_capture(文字列, パターン[, グループ番号])`、`regexp_replace(文字列, パターン, 置換)`。名前と引数の順は [sqlean-regexp](https://github.com/nalgeon/sqlean/blob/main/docs/regexp.md) に合わせ、パターンは JavaScript の正規表現（`u` フラグ付き）で解釈します
  ```sql
  SELECT regexp_capture('ヒャド属性ダメージ+7％', '^(.+)属性ダメージ([+-]\d+)([%％])$', 1); -- ヒャド
  ```
- 並べ替え・絞り込み（チップで表示）、CSV の読み込み/書き出し、`Ctrl+K` コマンドパレット
- **ファイルから開く・上書き保存**：「📂 ファイルから開く…」（ドラッグ＆ドロップ可）で `.sqlite` と `.sqlitesheet`（[プロジェクト](#プロジェクトのファイルsqlitesheet)）を開けます。中身はメモリにあり、`Ctrl+S` で保存します。Chrome / Edge では開いたファイルにそのまま上書きし、初めて保存するときは保存先（ブラウザ・`.sqlite`・`.sqlitesheet`）を選びます。開いた後にほかのアプリでファイルが変更されていれば、保存するときやタブに戻ったときに知らせて「上書き保存／読み直す」を選べます。未保存のまま閉じようとすると確認します。「最近開いたファイル」から開き直せます
- **ほかの DB の表を参照**：SQL に `DB名.表名` と書くだけで、その DB を読み取り専用でつないで（`ATTACH`）JOIN できます。例：`SELECT * FROM マスター.items AS i JOIN owned AS o USING (item_id)`。スペースや記号を含む名前は `"…"` で囲みます。クエリシート・SQL コンソール・セルの式で使えます（ビューは SQLite の制約でほかの DB を参照できません）
- **URL で開く・共有する**：開いている DB とシートは URL に出ます。Web 上の `.sqlite` ファイルを URL で開いたり、「🔗 共有…」でクエリシートやデータごと渡すリンクを作ったりできます（→ [URL で開く](#url-で開く)）
- **複数 DB**：作成・切替・名前変更・複製・削除と、ファイルへの書き出し（`.sqlite`・`.sqlitesheet`。保存先を選べます）。ブラウザに保存した DB は、変更のたびに自動で保存されます
- **スマホでも使えます**：表は二本指でつまむと、上下のバーはそのままで表だけを拡大縮小できます
  - ファイルを開くときは種類で絞らず中身で判定、書き出しは共有シート（「ファイルに保存」など）から（共有できない端末ではダウンロード）。上書き保存はできません
- 外部キー制約は常に有効（`PRAGMA foreign_keys = ON`）、GUI で作るテーブルは既定で `STRICT`

## URL で開く

> ファイル（`.sqlitesheet`）と URL で表せるものの正式な仕様は [docs/project-format.md](docs/project-format.md) です。

アドレスバーの URL が、そのまま「どの DB の、どのシートを開くか」になります。ブックマークにもできます。人に渡すときは「🔗 共有…」でリンクを作ります（→ [共有する](#共有する)）。

### 端末の DB を開く

```
/<DB 名>?sheet=<シート名>
```

| 例 | 開くもの |
|---|---|
| `/家計簿` | DB「家計簿」（シートは前回のもの） |
| `/家計簿?sheet=支出` | DB「家計簿」のテーブル（またはビュー）「支出」 |
| `/家計簿?sheet=~月別` | DB「家計簿」のクエリシート「月別」 |

- クエリシートは名前の前に `~` を付けます（テーブルとクエリが同じ名前でも区別できます）。名前そのものが `~` で始まるときは、その `~` を `~~` と重ねて書きます
- 日本語や空白はブラウザが自動でエンコードします。手で書くときはエンコードしなくても通ります
- DB はその端末のブラウザの中にしかないので、この URL を人に送っても相手には開けません（自分用のブックマーク向け）。人に見せたいときは「🔗 共有…」でデータごと埋め込んだリンクを作ります

### 選んだ範囲へのリンク（`#`）

セル・範囲・列・行を右クリックして「🔗 リンクを作る…」を選ぶと、その選択を開くリンクを作れます（→ [共有する](#共有する)。指し方や並べ替え・絞り込みを含めるかはそこで選びます）。選んだり並べ替えたりしただけでは URL は変わりません（スプレッドシートと同じ）。

```
/家計簿?sheet=支出#sort=日付:desc&filter=["分類","eq","食費"]&range=B3:D7
/家計簿?sheet=支出#range=R[42]C["金額"]:R[50]C["メモ"]
```

| キー | 書き方 |
|---|---|
| `sort` | `列名:asc` か `列名:desc`。いくつでも並べられ、前ほど優先 |
| `filter` | `["列名","条件","値"]`（JSON）。いくつでも並べられ、すべて満たす行に絞る |
| `range` | 選んでいる範囲。両端を `:` でつなぐ（1 つなら片側だけ）。書き方は下の 2 通りで、両端は同じ書き方・同じ形にする |

`range` の書き方：

| 選択 | 位置で（A1 形式） | 列名・主キーで（テーブルだけ） |
|---|---|---|
| セル | `B3` | `R[42]C["price"]` |
| 範囲 | `B3:D7` | `R[42]C["price"]:R[50]C["memo"]` |
| 列 | `B` / `B:D` | `C["price"]` / `C["price"]:C["memo"]` |
| 行（レコード） | `3` / `3:5` | `R[42]` / `R[42]:R[50]` |
| すべて | `all` | `all` |

- **位置で**：列は `A`, `B`… の表示上の位置、行は表示上の行番号（1 から）です。どのシートでも使えます。並べ替え・絞り込みも入るので、データが同じなら同じ範囲になります。データが変わる（行の追加・削除など）とずれます。ビュー・クエリで同じ値が並ぶと順番が定まらないこともあります
- **列名・主キーで**：`R[…]` は行の主キーの値の JSON 配列、`C[…]` は列名の JSON 文字列です。大カッコは省略できません
  - TEXT の主キーは `R["abc"]`、数値は `R[42]`（`R["42"]` とは別の行）、複合主キーは `R[4,"F-010"]`、主キーがなければ rowid
  - 列の並びやデータが変わっても同じ列・行を指します。範囲の間にどの行が入るかは、開いたときの並びで決まります。URL に主キーの値が入ります
- 開くとその範囲を選んで見える位置までスクロールします。リンクの `#` は、選択や並べ替えを変えるまで URL に残ります
- 見つからない（ない列・行、絞り込みで隠れている）ときは知らせて、選択なしで開きます。ない列の並べ替え・絞り込みは無視します
- `?sheet=` が書かれていないリンクでは、`sort`・`filter`・`range` は当てません（知らせます）
- `#db_embed=` と一緒に使うときは `#db_embed=…&range=…` のように `&` でつなぎます

### Web 上の .sqlite ファイルを開く（`?db=`）

```
/?db=<SQLite ファイルの URL>
```

例：`/?db=https://example.com/data/sample.sqlite`

- ファイルは**メモリに読み込んで**開きます。編集はできますが、保存するまで何も残りません
- 残したいときは「💾 保存…」（`Ctrl+S`）で保存先を選びます。「ブラウザに保存」なら名前を付けてブラウザの DB になり、以後はいつもどおり自動保存されます。`.sqlite`・`.sqlitesheet` ファイルにも保存できます
- 未保存の変更があるまま閉じたり、ほかの DB へ移ったりしようとすると確認します
- この URL は人に送っても同じものが開きます（開いた後の変更は、各自の手元にしか残りません）
- パスに名前を書くと、保存するときの名前の候補になります：`/売上2025?db=…`
- `?sheet=` も使えます：`/?db=…&sheet=商品`
- ファイルを置いたサーバーが、ほかのサイトからの読み込みを許している（CORS）必要があります。許していないと「ファイルを取得できませんでした」になります。同じサイトに置いたファイルなら `?db=/data/sample.sqlite` のようにパスだけで書けます

### クエリシートやシートの設定を添える（`sheets[n][…]=`）

`?db=`（か `#db_embed=`）に添えると、開いたときにクエリシートを足したり、シートの並び・列の幅などを決めたりできます。「このデータを、この切り口で見て」という URL を作って人に送るのに使えます。書き方の詳細は [仕様書](docs/project-format.md) です。

例（`商品` テーブルのある DB を開き、「高い順」というシートを開いた状態にする）：

```
/?db=https://example.com/shop.sqlite
  &sheets[0][type]=query
  &sheets[0][name]=高い順
  &sheets[0][sql]=SELECT * FROM 商品 ORDER BY 価格 DESC
  &sheet=~高い順
```

（読みやすく改行していますが、実際は1行につなげます。SQL の `;` `&` `#` `+` `=` などはエンコードが必要なので、`encodeURIComponent()` を通すのが確実です）

- **URL の書き方は開発中で、変わることがあります。** 長く残したいものは、次の「プロジェクトのファイル」を使ってください
- 以前の書き方（`query1=<SQL>&query1.name=<名前>`、`#data=`）も読み込めます
- 仕込んだクエリは、DB を保存すると一緒に残ります。クエリを書き換えたときも「未保存」になります
- **クエリシートは読み取りだけです。** `SELECT`（`WITH … SELECT` を含む）の1文だけが実行でき、`UPDATE` や `DELETE`、`;` で2文目をつなげたものは実行されずにエラーになります。リンクに書き換えの SQL が仕込まれていても、データは変わりません
- [ほかの DB の表を参照](#できること)する `DB名.表名` も使えます。その場合は、**リンクを開いた人の端末にある** 同じ名前の DB を（読み取り専用で）読みます

### プロジェクトのファイル（`.sqlitesheet`）

DB と、クエリシート・シートの並び・列の幅・行の高さ・セルの書式をひとまとめにしたファイルです。中身は JSON です（[仕様書](docs/project-format.md)）。

- **保存する**：開いているものの「💾 保存」「💾 別の場所に保存…」で `.sqlitesheet` を選びます。ブラウザの DB はファイルメニューの「📦 .sqlitesheet に書き出す…」。URL から開いて変更が無ければ DB はその URL を指し、それ以外は DB を埋め込みます
- **開く**：「📂 ファイルから開く…」かドラッグ＆ドロップで、メモリで開きます。`db` が相対パスのときは、その DB ファイルを選んでもらいます（ブラウザはパスからファイルを開けないため）
- **上書き保存**：開いた `.sqlitesheet` に `Ctrl+S` で上書きします。DB の指し方はファイルのとおりで、埋め込みなら中のデータを、パスなら（データが変わったときだけ）選んだ DB ファイルを書き換えます。DB を URL で指しているときは書き換えられないので、埋め込みに切り替えるか尋ねます
- **URL で開く**：Web に置いたファイルを `/?project=<.sqlitesheet の URL>` で開けます。ファイルの中の `db` が相対パスなら、そのファイルの場所が基準です。`?sheet=` と `#` の `sort`・`filter`・`range` も一緒に書けます

### 共有する

ファイルメニュー（またはコマンドパレット）の「🔗 共有…」で、開いている DB とシートを渡すリンクを作れます。セル・範囲・列・行の右クリックの「🔗 リンクを作る…」も同じ画面で、今の選択（`range`）も入ります。選択肢を変えると、下のリンクがすぐ変わります。

- **DB**：下の表の渡し方か、「DB を含めない」（端末の DB を開いているときだけ。`/<DB 名>?sheet=…` だけのリンクで、この端末か同じ名前の DB がある端末で開く）
- **選択範囲の指し方**（右クリックからのとき）：「位置で」（`range=B3:D7`）か「列名・主キーで」（`range=R[42]C["price"]`。テーブルで、主キーをリンクに書ける行だけ）。はじめに開くシートは今のシートに決まります
- **並べ替え・絞り込みを含める**：そのシートに並べ替え・絞り込みがあるときに選べます。「位置で」なら必ず含めます
- 含めるクエリシート（DB を含めるとき）と、はじめに開くシートを選べます。リンクに入るのはシートの並びとクエリシートだけで、列の幅などはプロジェクトのファイルで渡します
- 「🔗 リンクをコピー」でコピーし、スマホなどでは「📤 共有…」から OS の共有シートに渡せます
- 相手はリンクを開くと、`?db=` と同じようにメモリで開きます。残したければ相手が保存します。相手の変更がこちらに届くことはありません

DB の渡し方は4つです。

| 渡し方 | 使えるとき | リンク |
|---|---|---|
| 元のファイルの URL を使う | `?db=` などで開いているとき | `?db=<元の URL>&sheets[0][…]=…`。短い。未保存のデータの変更は含まれない |
| データごと埋め込む | いつでも（端末の DB・ローカルファイルも） | DB を圧縮して `#db_embed=…` に入れる。元のファイルがなくても開ける |
| 置いたファイルの URL を指定する | いつでも | 入力した URL を `?db=` に入れる。ファイルは自分で書き出してどこかに置く（相手のブラウザから読めること＝CORS が必要） |
| 置いたプロジェクトのファイルの URL を指定する | いつでも | 入力した URL を `?project=` に入れる。クエリシートや列の幅は、そのファイルのものになる |

- 埋め込みリンクは `#` 以降にデータが入るので、サーバーには送られません。ただし**リンクを知っている人は中身を見られます**
- 長さの目安：数 KB の DB ならリンクは数百〜数千文字です。8,000 文字を超えると、チャットアプリなどで途中で切れることがあると知らせます。約 200 万文字を超える場合は作れないので、「ファイルに書き出す」でファイルを渡してください
- ほかの DB を `DB名.表名` で参照しているクエリを含めると、相手の端末に同じ名前の DB がないと動かないことを知らせます

### PWA（ホーム画面に追加したアプリ）から開く

PWA にはアドレスバーがないので、ホームとメニューに「🌐 URL から開く…」が出ます。次のどれを貼っても開けます。

- このアプリの URL（`?db=`・`?project=`・`?sheet=`・`sheets[…]`・`queryN=` か、`#` に `db_embed`・`data`・`range`・`sort`・`filter` のどれかが付いたもの）：クエリやシート、選択の指定ごと、そのとおりに開きます。公開版など、別のアドレスのこのアプリの URL でもかまいません。DB を含めないリンクは、この端末の同じ名前の DB を開きます（なければ知らせます）
- `.sqlite` ファイルの URL：`?db=` に指定したのと同じです
- `.sqlitesheet` ファイルの URL：`?project=` に指定したのと同じです

## 動かし方

ビルド不要のバニラ JS（ES Modules）です。静的ファイルとして配信するだけで動きます。

URL は `/<DB 名>?sheet=<シート名>` の形で、DB をパスで表します（[URL で開く](#url-で開く)）。そのため、存在しないパスにも `index.html` を返す（SPA フォールバック）サーバーで配信してください。ローカルでは `tools/dev-server.py`（Python 標準ライブラリだけで動きます）を使います。SPA フォールバックに加えて、`sw.js` と `js/version.js` を配るときに版の `dev` を「dev-ファイルの最新の更新日時」に差し替えるので、保存するたびに Service Worker が入れ直され、ホーム画面の版表示で最新を読めているか確かめられます。

```sh
python tools/dev-server.py --port 8000
# → http://localhost:8000/
# スマホから確かめるときは HTTPS で: --cert lan.crt --key lan.key
```

### 仕様書を作り直す

プロジェクトの形式の仕様は、元を [docs/openapi.json](docs/openapi.json)（OpenAPI 3.1）に書き、人が読む [docs/project-format.md](docs/project-format.md) はそこから作ります。仕様を変えたら作り直して、両方を同じコミットに入れてください。合っていないと GitHub Actions（`.github/workflows/spec.yml`）が失敗します。

```sh
python tools/gen-spec.py          # 作り直す
python tools/gen-spec.py --check  # 合っているか確かめる
```

### GitHub Pages で公開

`main` に push すると `.github/workflows/pages.yml` が公開します（Settings → Pages の Source は GitHub Actions）。公開する前に版をコミットハッシュに書き換えます。
GitHub Pages は SPA フォールバックを設定できないため、`404.html` が元の URL を預けてアプリの入口へ転送し、アプリ側で元の URL に戻します。
COOP/COEP ヘッダーは不要です（SharedArrayBuffer を使わない `opfs-sahpool` VFS を採用）。

## しくみ

| ファイル | 役割 |
|---|---|
| `js/db-worker.js` | Worker 内で sqlite-wasm を動かし、`opfs-sahpool` に DB ごとのファイルを置く |
| `js/regexp.js` | 正規表現の SQL 関数（DB を開くたびに Worker が登録する） |
| `js/db-client.js` | Worker との RPC。発行した SQL を履歴に流す |
| `js/store.js` | DB ごとの端末側データ（保存クエリ・並び順・列幅）。DB の名前変更・複製・削除に追従 |
| `js/project.js` | プロジェクト（`.sqlitesheet` ファイルと URL）の読み書き。仕様は `docs/openapi.json` |
| `js/files.js` | ファイルから開く・上書き保存の補助：最近開いたファイル（ファイルハンドルだけを IndexedDB に保存）と読み書きの許可 |
| `js/schema.js` | スキーマの読み取り、CREATE TABLE の生成、テーブル再作成 SQL |
| `js/grid.js` | 仮想スクロールのグリッド（選択・編集・コピペ） |
| `js/i18n.js` | 画面の言語（日本語・英語）。日本語の文をキーにして、英語のときは `js/locales/en.js` の訳を使う。初期値は端末の言語で、ホームと「ツール」メニューから切り替えられる |
| `js/blob.js` | BLOB の中身の種類の判定（先頭のバイトで画像・PDF・テキストなどを見分ける）と 16 進ダンプ |
| `js/sources.js` | テーブル／クエリをグリッドにつなぐ（UPDATE/INSERT/DELETE と Undo 記録） |
| `js/design-panel.js` | 設計パネル |
| `js/console.js` | SQL コンソール |
| `js/main.js` | 画面全体・DB/シート管理 |
| （外部）| 公式 [`@sqlite.org/sqlite-wasm`](https://www.npmjs.com/package/@sqlite.org/sqlite-wasm) 3.54.1-build1 を jsDelivr から ES module として import（`js/db-worker.js`） |

DB の中にはアプリ用のデータを書き込みません。クエリシートの SQL・シートの並び順・列の幅などは端末の localStorage に DB ごとに保存されるので（`js/store.js`）、書き出した `.sqlite` ファイルには含まれません。一緒に渡したいときは「プロジェクトとして書き出す」を使います。

## 注意

- 同時に開けるのは 1 タブだけです（`opfs-sahpool` の制約）
- 正規表現の関数はこのアプリが登録するもので、DB ファイルには入りません。これを使ったビューやトリガーを含む `.sqlite` ファイルを、ほかのツールで開いて使うと、そのツールに同じ関数がない限り「no such function」のエラーになります（たとえば `sqlite3` コマンドは `REGEXP` だけを持っています）
- Undo はデータ編集（セル・行の追加/削除・貼り付け）が対象です。構造の変更や SQL コンソールでの変更は取り消せません。大事なデータは書き出してバックアップしてください
- ブラウザに保存した DB は OPFS（ブラウザのサイトデータ）にあります。サイトデータを消すと DB も消えます。大事なものは「.sqlite に書き出す」で保存してください
- ファイルから開いたものは中身をメモリに読み込むので、保存しないままブラウザが落ちると変更は失われます。保存のたびにファイル全体を書き直すので（一時ファイルに書いてから差し替えるため、保存中に落ちても元のファイルは壊れません）、数百 MB を超えるような大きな DB には向きません
